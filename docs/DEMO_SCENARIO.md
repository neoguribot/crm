# 4분 발표 시나리오 (DEMO_SCENARIO)

- 전제:
  - `docs/DEMO_DATA.md` 대로 샘플 데이터 적용 완료 (고객 18 / 거래 24)
  - **데모 계정 준비 여부**: 이메일·비밀번호를 미리 확인해 둔다 (값은 여기 적지 않는다).
    로그인 실패에 대비해 대체 계정도 하나 준비.
  - 상단 **공통 네비게이션**(대시보드 · 고객관리 · 리마인드 · 로그아웃)으로 이동 가능.
- 총 6개 장면, 각 30~50초, 합계 약 4분

## 발표 전 준비 (탭·화면)

1. `npm run dev` 실행 (또는 `npm run build && npm run start`), http://localhost:3000 확인
2. 브라우저 탭 **1개만** 열어둔다: `http://localhost:3000/login` (로그아웃 상태)
3. 창 폭은 발표용 노트북 기준으로 넓게 (대시보드 카드가 4열로 보이는 너비)
4. 개발자 도구·불필요한 확장 프로그램 창은 닫는다
5. 입력할 값(아래 장면 3)을 손 닿는 곳에 메모

---

## 장면 0 · 로그인 + 파이프라인 (~25초)

- **클릭**: http://localhost:3000 → (미인증이면) 로그인 화면 → 이메일·비밀번호 입력 → 로그인
- **이동**: `/pipeline` (기본 화면 = 영업 파이프라인)
- **짚을 것**: 신규 문의 → 상담 중 → 견적 발송 → 구매 확정 → 사후 관리 5개 컬럼.
  카드를 드래그하거나 이전·다음 버튼으로 단계를 옮긴다.
- **대사**: "금은방 사장님이 쓰는 고객관리 CRM입니다. 로그인하면 바로 영업 파이프라인이 뜨고,
  고객이 어느 단계에 있는지 한눈에 봅니다. 상단 메뉴로 대시보드·고객관리·리마인드로 이동합니다."

## 장면 1 · 대시보드 (~45초)

- **클릭**: 네비게이션 **대시보드**
- **짚을 것**:
  - 전체 고객 **18명**
  - 이번 달 **판매 5,920,000원 / 매입 1,030,000원** — "판매와 매입을 절대 합치지 않습니다"
  - 구매목적별 고객 수 (돌반지 5 · 투자·골드바 7 · 매입 6 · 예물 5 · 기타 1)
  - **90일 이상 미방문 5명**, **30일 이내 이벤트 예정 11명**
  - 최근 거래 5건 — 고객 이름 클릭 시 상세로
- **대사**: "집계는 전부 PostgreSQL 함수 한 번으로 계산합니다. 이번 달 매출, 오랫동안 안 오신 고객, 곧 챙겨야 할 이벤트를 한눈에 봅니다."

## 장면 2 · 고객 검색·세그먼트 (~50초)

- **클릭**: 상단 네비게이션 **고객관리** (또는 대시보드 "전체 고객" 카드) → `/customers`
- **시연**:
  1. 구매목적 = **돌반지** → 검색 → 5명
  2. 여기에 유입경로 = **당근마켓** 추가 → 도하준 1명 (상단에 조건 Badge 2개)
  3. "전체 초기화"
  4. 미방문 = **90일 이상** → 5명 (남해린·박도윤·안유찬·유하람·정해원)
  5. 새로고침 → 필터 그대로 (URL 파라미터)
- **대사**: "이름은 정확히, 연락처는 하이픈 없이도 검색됩니다. 구매목적·유입경로·미방문 기간을 조합해서 '투자 고객 중 90일 이상 안 오신 분' 같은 세그먼트를 바로 뽑습니다. 최근 방문일은 저장하지 않고 거래 기록으로 계산합니다."

## 장면 3 · 고객 등록 + 거래 기록 (~50초)

- **클릭**: 네비게이션 **고객관리** → "신규 고객 등록"
- **입력할 신규 고객**:
  | 필드 | 값 |
  | --- | --- |
  | 이름 | `데모 발표고객` |
  | 연락처 | `01099998888` (→ 자동으로 `010-9999-8888`) |
  | 유입경로 | 네이버플레이스 |
  | 최초 방문일 | 오늘 |
  | 구매목적 | 예물 + 투자·골드바 (2개 체크) |
- **저장** → 생성된 상세로 이동
- **클릭**: 상세에서 "거래 기록 추가"
- **입력할 거래**:
  | 필드 | 값 |
  | --- | --- |
  | 거래구분 | 판매 |
  | 품목 | 18K |
  | 중량 | `5.2` |
  | 금액 | `1350000` |
  | 순도 | `75` |
  | 거래일 | 오늘 |
- **저장** → 상세 하단 거래 이력에 `1,350,000원` 표시
- **대사**: "연락처는 입력하면 하이픈이 자동으로 붙습니다. 금액·중량·순도는 소수점이 깨지지 않게 문자열로 다루고, 화면에는 천 단위로 보여줍니다."

## 장면 4 · 거래 이력 (~30초)

- **클릭**: 네비게이션 **고객관리** → 검색창에 `데모 도하준` → 검색 → 행 클릭 → 상세
- **짚을 것**: 거래 이력 2건, **같은 날짜**, 거래일 내림차순, ▲판매/▼매입 구분
- **대사**: "고객별 거래는 상세 화면 안에서 최신순으로 봅니다. 같은 날 여러 건도 순서대로 정리됩니다."

## 장면 5 · 리마인드 (~45초)

- **클릭**: 네비게이션 **리마인드** (또는 대시보드 "30일 이내 이벤트 예정" 카드) → `/reminders`
- **시연**:
  1. 탭 "기한 지남" → 4명, **가장 오래 지난 안유찬(-30일)** 이 맨 위
  2. 탭 "7일 이내" → 5명 (오늘이 이벤트인 **도하준** 포함)
  3. 아무 고객의 **연락처 클릭** → "복사됨"
  4. "고객 상세" 버튼 → 상세로
- **대사**: "다음 이벤트 예정일로 연락 대상을 자동 분류합니다. 기한이 지난 고객은 가장 오래 지난 분부터 보여줘서 먼저 챙기게 합니다. 연락처는 클릭하면 복사돼서 바로 전화나 문자에 붙여넣습니다. 문자 발송 자체는 이번 범위가 아닙니다."

## 마무리 (~10초)

- **대사**: "고객 등록·조회·수정, 거래 기록, 검색·세그먼트, 대시보드, 리마인드 — MVP 5개 기능을 Next.js + Supabase로 구현했고, 모든 접근은 Row Level Security로 사장님 본인 데이터만 열립니다."

## 오류 시 대체 흐름

| 문제 | 대체 |
| --- | --- |
| 대시보드가 오류 카드 | `select public.dashboard_summary();` 를 SQL Editor 에서 실행해 확인. 안 되면 `0002` 마이그레이션 재적용 |
| 신규 고객 등록이 실패 | 이미 만든 샘플 고객(데모 조가율 등)으로 장면 3의 "거래 등록"만 진행 |
| 거래 등록이 실패 | 데모 도하준 상세의 기존 거래 2건으로 장면 4 로 바로 이동 |
| 리마인드가 비어 보임 | 샘플 적용 후 시간이 많이 지났을 수 있음 → `[DEMO]` 제거 후 `demo_data.sql` 재실행 (날짜가 오늘 기준으로 다시 계산됨) |
| 검색 결과가 예상과 다름 | 필터 Badge 를 모두 지우고 다시 하나씩. `?` 뒤 파라미터 오타 확인 |
| 로그인이 안 됨 | Supabase > Authentication > Users 에서 비밀번호 재설정, 또는 새 테스트 사용자 생성 후 `demo_data.sql` 을 그 UUID 로 재적용 |
| 화면이 깨짐 | `npm run build` 후 `npm run start` 로 프로덕션 모드 사용 |

## 발표 중 절대 하지 말 것

- 실제 고객 데이터 입력 (샘플만 사용)
- 샘플 제거 SQL 실행
- Supabase 대시보드에서 RLS 끄기
- `.env.local` / 키 화면 노출
