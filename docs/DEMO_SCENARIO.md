# 발표 시나리오 (DEMO_SCENARIO)

- 전제:
  - `docs/DEMO_DATA.md` 대로 샘플 데이터 적용 완료 (고객 18 / 거래 24 / 일정 6)
  - **데모 계정 준비 여부**: 이메일·비밀번호를 미리 확인해 둔다 (값은 여기 적지 않는다).
    로그인 실패에 대비해 대체 계정도 하나 준비.
  - 상단 **공통 네비게이션**(홈 · 고객관리 · 거래관리 · 시세관리 · 캘린더 · 종합분석 · 로그아웃)으로 이동 가능.
- 총 7개 장면, 각 30~50초, 합계 약 5분

## 발표 전 준비 (탭·화면)

1. `npm run dev` 실행 (또는 `npm run build && npm run start`), http://localhost:3000 확인
2. 브라우저 탭 **1개만** 열어둔다: `http://localhost:3000/login` (로그아웃 상태)
3. 창 폭은 발표용 노트북 기준으로 넓게 (대시보드 카드가 여러 열로 보이는 너비)
4. 개발자 도구·불필요한 확장 프로그램 창은 닫는다
5. 입력할 값(아래 장면 4)을 손 닿는 곳에 메모

---

## 장면 0 · 로그인 + 홈 대시보드 (~40초)

- **클릭**: http://localhost:3000 → (미인증이면) 로그인 화면 → 이메일·비밀번호 입력 → 로그인
- **이동**: `/home` (기본 화면)
- **짚을 것**:
  - "오늘의 고객 관리 일정" 위젯 — 상태 탭(기한 지남/7일 이내/30일 이내/전체 예정)으로
    바로 필터링. 샘플 기준 기본 목록에 **6건**이 뜬다.
  - 거래 고객 수(오늘/어제/이번 주/이번 달/올해 누적)
  - 이번 달 매출 지표(판매 **5,920,000원** / 매입 **1,030,000원** / 총합)와
    목표 도달 현황(목표값은 홈에서 바로 수정 가능)
- **대사**: "금거래소 사장님이 쓰는 CRM입니다. 로그인하면 홈 화면에 오늘 챙겨야 할 일정과
  매출 지표, 목표 도달 현황이 한 화면에 모여 있습니다."

## 장면 1 · 고객 검색·세그먼트 (~50초)

- **클릭**: 상단 네비게이션 **고객관리** (또는 홈 "전체 고객" 카드) → `/customers`
- **시연**:
  1. 방문목적 = **돌제품** → 검색 → 5명
  2. 여기에 유입경로 = **당근마켓** 추가 → 도하준 1명 (상단에 조건 Badge 2개)
  3. "전체 초기화"
  4. 방문일 구간 필터로 오래 방문 안 한 고객 조회
  5. 새로고침 → 필터 그대로 (URL 파라미터)
- **대사**: "이름은 정확히, 연락처는 하이픈 없이도 검색됩니다. 방문목적·유입경로·방문일
  구간을 조합해서 세그먼트를 바로 뽑습니다. 최근 방문일은 저장하지 않고 거래 기록으로 계산합니다."

## 장면 2 · 고객 상세 — 등급·일정·거래 이력 (~40초)

- **클릭**: 고객 목록에서 **데모 도하준** 클릭 → 상세
- **짚을 것**:
  - 고객 정보에 성별·등급(등급 미지정이면 자동 추천 배지도 함께 표시)
  - 거래 이력 2건 — **같은 날짜**, 거래일 내림차순, ▲판매/▼매입 구분, 완료 여부 표시
  - 일정 섹션 — 거래와 연동해 등록 가능(진행 중인 맞춤 주문 건 등)
- **대사**: "등급은 사장님이 직접 정하시되, 누적 거래액 기준 참고 배지를 함께 보여드립니다.
  일정은 문의·예약·맞춤주문 등 종류별로 여러 건을 동시에 관리하고, 진행 중인 거래와도 연결할 수 있습니다."

## 장면 3 · 고객 등록 + 거래 기록 (~50초)

- **클릭**: 네비게이션 **고객관리** → "신규 고객 등록"
- **입력할 신규 고객**:
  | 필드 | 값 |
  | --- | --- |
  | 이름 | `데모 발표고객` |
  | 연락처 | `01099998888` (→ 자동으로 `010-9999-8888`) |
  | 성별 | 여성 |
  | 유입경로 | 네이버플레이스 |
  | 방문목적 | 주얼리 맞춤 + 골드바 (2개 체크) |
  | 고객 등록일 | 오늘 |
- **저장** → 생성된 상세로 이동
- **클릭**: 상세에서 "거래 기록 추가"
- **입력할 거래**:
  | 필드 | 값 |
  | --- | --- |
  | 거래구분 | 판매 |
  | 품목 | 18K |
  | 중량 | `5.2` |
  | 기준 단가 | `237,000` |
  | 총 금액 | `1,232,400` |
  | 완료 여부 | 완료 |
  | 거래일 | 오늘 |
- **저장** → 상세 하단 거래 이력에 표시, **마지막 연락일이 자동으로 오늘로 갱신**됨을 짚는다.
- **대사**: "연락처는 입력하면 하이픈이 자동으로 붙습니다. 거래를 등록하면 마지막 연락일이
  자동으로 갱신됩니다. 금액·중량은 소수점이 깨지지 않게 문자열로 다룹니다."

## 장면 4 · 거래관리 + 시세관리 (~45초)

- **클릭**: 네비게이션 **거래관리** → `/transactions`
- **시연**: 검색창에 `데모 도하준` → 방금 만든 거래 목록에서 확인, "신규 거래 등록" 버튼으로
  고객을 직접 선택해 거래를 새로 등록할 수도 있음을 보여준다. 거래 행 클릭 → 상세에서 수정·삭제.
- **클릭**: 네비게이션 **시세관리** → `/prices`
- **시연**: 오늘 시세를 새로 등록(등록할 때마다 이력으로 쌓임, 하루에 여러 번 등록 가능).
  목표가에 도달한 고객이 있으면 알림이 생성됨을 설명. 시세 이력 목록에서 과거 값 수정도 가능.
- **대사**: "거래는 고객 상세뿐 아니라 거래관리 화면에서 전체를 검색·수정·삭제할 수 있습니다.
  시세는 변동값이라 등록할 때마다 새 이력으로 쌓이고, 매수 희망가에 도달하면 알림이 뜹니다."

## 장면 5 · 캘린더 + 종합분석 (~40초)

- **클릭**: 네비게이션 **캘린더** → `/calendar`
- **짚을 것**: 이번 달 그리드에서 일정이 있는 날짜에 종류·고객명 미리보기, 클릭하면 하단에 상세 목록
- **클릭**: 네비게이션 **종합분석** → `/analytics`
- **짚을 것**: 성별·등급·연령대·유입경로 분포, 누적 거래액 상위 고객 랭킹(집계는 DB에서 계산)
- **대사**: "캘린더로 한 달 일정을 한눈에 보고, 종합분석에서 고객 구성과 매출 기여도가 높은
  고객을 확인합니다."

## 마무리 (~10초)

## 오류 시 대체 흐름

| 문제 | 대체 |
| --- | --- |
| 홈 화면이 오류 카드 | `select public.dashboard_summary();` 를 SQL Editor 에서 실행해 확인. 안 되면 `0015`/`0018` 마이그레이션 재적용 |
| 신규 고객 등록이 실패 | 이미 만든 샘플 고객(데모 조가율 등)으로 장면 3의 "거래 등록"만 진행 |
| 거래 등록이 실패 | 데모 도하준 상세의 기존 거래 2건으로 장면 2 로 바로 이동 |
| 홈 일정 위젯이 비어 보임 | 샘플 적용 후 시간이 많이 지났을 수 있음 → `[DEMO]` 제거 후 `demo_data.sql` 재실행(날짜가 오늘 기준으로 다시 계산됨) |
| 검색 결과가 예상과 다름 | 필터 Badge 를 모두 지우고 다시 하나씩. `?` 뒤 파라미터 오타 확인 |
| 로그인이 안 됨 | Supabase > Authentication > Users 에서 비밀번호 재설정, 또는 새 테스트 사용자 생성 후 `demo_data.sql` 을 그 UUID 로 재적용 |
| 화면이 깨짐 | `npm run build` 후 `npm run start` 로 프로덕션 모드 사용 |

## 발표 중 절대 하지 말 것

- 실제 고객 데이터 입력 (샘플만 사용)
- 샘플 제거 SQL 실행
- Supabase 대시보드에서 RLS 끄기
- `.env.local` / 키 화면 노출
